# 매장 전화번호·사업자번호 입력

## 적용 범위와 저장

매장 등록 및 수정의 입력 폼에만 자동 표시를 적용합니다. 기존 GET 응답 필드와 조회 파서는 그대로입니다. 원본 DB 행을 일괄 변경하거나 실제 Azure DB에 쓰지 않습니다.

| 항목 | 화면 표시 | POST/PATCH와 저장 |
| --- | --- | --- |
| 전화번호 | 010-1234-5678, 02-123-4567, 1588-1234 등 | 지원 형식 검증 후 하이픈 포함 표준 문자열, store_phone VARCHAR(50) |
| 사업자번호 | 000-00-00000 | 구분자 제거한 숫자 10자리 문자열, business_no CHAR(10) |

숫자와 ASCII 공백·괄호·하이픈을 입력/붙여넣기할 수 있습니다. 구분자는 정상 표시로 정리하지만 문자·국제번호의 +·내선·다른 유니코드 문자는 몰래 제거하지 않고 검증 실패로 처리합니다. 초과 숫자도 잘라서 다른 유효 번호로 만들지 않습니다. 전화번호의 실제 개통·명의·할당 여부, 사업자번호의 실재 여부·체크섬은 검사하지 않습니다. 중복 허용 정책은 유지합니다.

서버도 같은 정책으로 전화번호를 하이픈 포함 문자열로, 사업자번호를 숫자 10자리로 정규화합니다. 기존 숫자 10자리 사업자번호 API 요청도 그대로 받으며 형식이 맞는 구분자 포함 요청도 정규화합니다. 새 필드·엔드포인트·DB 제약을 추가하지 않았습니다.

## 지원하는 전화번호 형태

이 프로젝트가 지원하는 주요 국내 형식의 명시적 범위입니다. 모든 통신서비스 번호를 완전히 판별하는 시스템이 아닙니다.

| 접두부 | 총 숫자 수 | 표시 |
| --- | --- | --- |
| 010 | 11 | 010-0000-0000 |
| 02 | 9 또는 10 | 02-000-0000 / 02-0000-0000 |
| 031·032·033, 041·042·043·044, 051~055, 061~064 | 10 또는 11 | 000-000-0000 / 000-0000-0000 |
| 070 | 11 | 070-0000-0000 |
| 080 | 10 | 080-000-0000 |
| 15xx·16xx·18xx | 8 | 1588-0000 등 |

국제번호(+82), 내선, 050 계열·기타 특수서비스·과거 이동전화 접두부 등은 이번 신규/변경 입력 범위에 포함하지 않습니다. 해당 기존 값이 있더라도 수정하지 않으면 보존합니다. 번호 개통/국번 할당 정보를 조회하지 않으므로 지원 접두부 및 길이에 맞는 모든 숫자 조합을 허용합니다.

참고한 공식 번호 자료:
- [국가법령정보센터 전기통신번호관리세칙](https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulSeq=2100000095072): 010/070 식별번호와 국번호 구성 참고. 구현의 지원 범위 표를 모든 현행 법적 허용 번호의 목록으로 해석하지 않습니다.
- [중앙전파관리소 발신번호 관련 안내](https://www.crms.go.kr/download.do?uuid=1f391ab0-28c7-4c14-af33-f5aaf364c1c3): 대표번호 예시 참고.

## 기존 데이터 보존

수정 화면은 원본을 별도로 유지합니다.
- 신규 등록은 모든 입력을 검증합니다.
- 원본이 비표준이면 열기·포커스·다른 필드 수정만으로 표시나 저장 값을 정정하지 않습니다.
- 정상 번호는 입력 폼에서 하이픈 표시를 제공하지만 구분자만 다른 같은 번호는 변경으로 판단하지 않습니다.
- 수정하지 않은 비표준 전화번호·사업자번호·우편번호 등은 검증 및 PATCH에서 제외합니다.
- 실제로 번호를 변경하면 새 입력 정책으로 검증하고 해당 필드만 PATCH합니다.
- GET 조회·기존 상세 표시·DB 데이터는 표시 목적의 포맷팅 때문에 바뀌지 않습니다.

예: 전화번호 legacy-phone, 사업자번호 OLD, 우편번호 T0001인 매장의 이름 수정은 PATCH에 store_name만 넣습니다. 전화번호를 직접 변경하면 지원하는 국내 형식이어야 합니다.

## 입력 동작

추가 패키지 없이 NumberInput 공통 입력을 사용합니다. 숫자의 논리적 위치로 커서/선택 위치를 복원하고, 구분자 옆 Backspace/Delete는 인접 숫자를 삭제해 하이픈 재삽입으로 커서가 갇히지 않게 합니다. 선택 삭제·전체 교체·중간 입력·붙여넣기를 지원하고 조합 입력 중에는 자동 포맷을 보류합니다. 터치 키보드에서 keydown 없이 발생하는 구분자 삭제도 inputType으로 처리합니다.

기존 필수값 안내·항목별 검증·저장 중 잠금·CSRF·세션 만료 처리·고정 하단 저장/취소·성공 후 공유 조회 갱신은 유지합니다. 실물 모바일 키보드 종류별 동작을 모두 검증한 것은 아닙니다.

## 테스트 구성

- src/test/number-cases.json은 프론트와 Python 테스트가 함께 읽는 계약 사례입니다.
- TS koreanNumbers와 Python korean_numbers의 허용/거부·정규화 결과를 같은 사례로 검증합니다.
- API 테스트는 SQLite 메모리 DB와 실제 세션·CSRF 준비를 사용하고 Azure 접속은 차단합니다. 서버 운영 코드는 프론트엔드 파일에 의존하지 않습니다.
- 기존 쓰기 테스트의 신규 등록 전화번호 예시를 이번 규칙에 맞는 전체 번호로 변경했습니다. 기존 DB 행의 짧은 비표준 번호는 그대로 두어 조회·수정 호환성 검증을 유지했습니다. 전화번호는 이제 길이 50자만으로 유효하지 않으므로 기존 최대길이 성공 입력을 정상 번호로 변경했고, 길이 초과 거부와 새 형식 검증을 유지·추가했습니다.
