## 접근과 인증 범위

- 기본 개발 주소: http://localhost:8080/login 또는 http://127.0.0.1:8080/login
- 기존 관리자 화면: 같은 호스트의 / 경로
- 사이드바 아래 로그인 UI 미리보기 링크와 로그인 화면의 기존 관리자 화면 링크 제공
- AppEntry가 문서 진입 경로 /login 및 /login/을 구분합니다. 별도 라우팅 라이브러리는 없습니다.
- 링크는 문서 단위 이동입니다. 기존 App 내부 6개 화면 전환·공유 조회 구조는 변경하지 않습니다.
- 로그인 경로는 실제 App을 렌더링하지 않아 관리 데이터 조회 로더를 실행하지 않습니다.
- 기존 / 경로는 인증 가드 없이 그대로 실행됩니다. /login이 접근 통제를 제공한다고 표시하지 않습니다.
- 정적 호스팅에서는 /login 직접 접근에 index.html fallback 설정이 필요합니다.

## 로그인 UI

기존 색상·폰트·카드·Heading·디자인 토큰과 lucide-react 아이콘을 재사용합니다.
440px 최대 폭의 폼은 화면 중앙에 놓이고 좁거나 낮은 화면에서는 문서 스크롤로 접근합니다.

- 관리자 ID: 문자열 입력란 + numeric 입력 힌트. 현재 양수 MySQL INT 범위인 1~2147483647을 검증합니다.
- 관리자 ID 앞뒤 공백은 제거하며 0·음수·소수·지수·문자·앞자리 0·범위 초과는 거부합니다.
- 비밀번호: 필수 입력, 기본 숨김, 표시/숨기기 버튼과 aria-pressed 제공.
- 필드별 오류·aria-invalid·설명 연결·첫 오류 필드 포커스 제공.
- Enter와 로그인 버튼 모두 같은 검증을 수행합니다.
- 유효한 제출도 인증 미연동 안내만 표시하며 비밀번호와 표시 상태를 초기화합니다.
- 앱은 비밀번호를 API·콘솔·localStorage·sessionStorage로 보내지 않습니다.
- 로그인 성공·가짜 세션·토큰·리다이렉트·계정 생성은 없습니다.
- AdminLoginForm은 검증된 입력을 전달하는 경계와 notice/error 피드백 구조를 갖고 있습니다.
  현재 LoginPage의 핸들러는 입력값을 사용하지 않고 미연동 안내만 표시합니다.
- 인증 오류 메시지는 일반 React 텍스트로 렌더링합니다. HTML로 해석하지 않습니다.

## 실제 브라우저 반응형 검증

Chrome 155.0.8059.85의 headless 브라우저에서 DOM 치수 측정과 스크린샷 육안 점검을 수행했습니다.
8080이 이미 사용 중이어서 검증 서버만 127.0.0.1:8180으로 실행했습니다. 프로젝트 기본 포트는 8080 그대로입니다.
실제 API 모드의 HTTP 응답을 검증용 데이터로 가로채었으며 실제 FastAPI·Azure DB에 요청하지 않았습니다.

| 뷰포트 | 검증 화면 | 결과 |
| --- | --- | --- |
| 1440 × 900 | 로그인 + 기존 6개 화면·상세 모달 | 페이지 가로 넘침 없음, 표 내부 가로 스크롤 유지 |
| 1024 × 900 | 동일 | 동일, 데스크톱 사이드바 유지 |

총 56개 치수·상태 표본에서 페이지 가로 넘침과 모달 닫기 버튼 잘림이 발견되지 않았습니다.
기존 6개 화면의 보이는 버튼·입력·선택 컨트롤은 최소 44px 높이를 확인했습니다.
추가로 알림 오류·재시도 중 로딩·정상 빈 목록과 로그인 필드 오류 화면을 확인했습니다.
Chrome 앱 런타임 예외는 발견되지 않았습니다.

미검증: 실제 Azure 데이터, 실제 모바일·태블릿의 터치·가상 키보드,
Safari·Firefox·다른 브라우저 버전, 브라우저 확대/축소 및 보조공학 실기기 테스트.
자동 테스트만으로 모든 환경의 반응형·접근성 검증을 완료했다고 간주하지 않습니다.

## 후속 인증 API 연결

1. 관리자 로그인 식별자·비밀번호 해시·세션·권한 계약을 먼저 확정합니다.
2. LoginPage 제출 핸들러에 별도 인증 요청 계층을 연결하고, 대기·401·403·503 등 안전한 오류를 분류합니다.
3. 성공 여부는 서버 검증 결과로만 결정합니다. 현재 안내 상태를 로그인 상태로 재사용하지 않습니다.
4. HttpOnly 쿠키 방식이면 credentials·CORS·CSRF·HTTPS 설정을 함께 적용합니다.
5. 로그아웃·만료·계정 변경 시 기존 App의 공유 조회 결과와 상세 화면을 초기화합니다.
6. /login 미리보기와 실제 접근 가드는 별도 변경으로 구현·검증합니다.
7. 등록·수정·점주 연결·기기 상태 변경·알림 확인은 인증·권한과 DB 승인 후 별도 개발합니다.
