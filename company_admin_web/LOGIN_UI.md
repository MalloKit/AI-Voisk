# 관리자 로그인 UI와 세션 연결 (2026-10-27)

기존 /login 미리보기를 실제 관리자 인증에 연결했습니다.
서버 계약·운영 제약·비밀번호 설정 절차는 [server/AUTH.md](../server/AUTH.md)를 참고하세요.

## 진입과 상태

- / 및 /login 모두 AppEntry에서 GET /auth/admin/me를 확인합니다.
- 확인 중에는 관리 화면과 데이터 로더를 실행하지 않습니다.
- 서버 인증 성공 후에만 기존 App을 마운트하고 /로 이동합니다.
- 미인증·만료는 /login, 서버 연결 실패는 로그인 화면의 오류·세션 재확인으로 구분합니다.
- 로그인 입력은 정수 관리자 ID·필수 비밀번호·표시/숨기기·필드별 오류·첫 오류 포커스를 유지합니다.
- 제출 중 입력·표시 버튼·로그인 버튼을 비활성화하고 로그인 중 상태를 표시합니다.
- 실패 시 ID/비밀번호 오류, Origin/CSRF 또는 권한 오류, 입력 길이 오류, 시도 제한, 서버 오류를 안전한 문구로 구분합니다.
- 입력 비밀번호는 제출 후 비우며 성공은 서버 응답으로만 결정합니다.
- 상단·사이드바에는 서버에서 확인한 관리자 이름·ID를 표시하고 사이드바에 로그아웃 버튼을 제공합니다.
- 인증 없는 관리자 진입 링크·미연동 안내·고정 시연 계정 문구를 제거했습니다.
- Mock은 조회 데이터 출처 설정이며 로그인 성공을 만드는 인증 모드가 아닙니다.

## 캐시와 요청

- 기존 5개 Repository의 파싱·검증·API 경로는 유지하고 공통 요청 경계에 credentials: include를 적용합니다.
- 보호된 조회의 401은 세션 만료 이벤트로 AppEntry에 전달하며 취소된 이전 요청은 만료 이벤트를 만들지 않습니다.
- 403·DB 503을 401로 취급하거나 Mock으로 대체하지 않습니다.
- 로그아웃·만료 시 App을 내리므로 useAsync 정리로 요청을 취소하고 공유 목록·상세·필터를 폐기합니다.
- 다시 로그인하면 새 App과 새 기본 Mock Repository를 사용합니다.
- 60초 주기 및 포커스/가시성 복귀 확인은 정상일 때 기존 App을 유지하므로 화면 이동·조회 상태를 초기화하지 않습니다.
- 로그아웃 요청 실패는 데이터 화면을 숨긴 상태에서 재시도하며 완료라고 표시하지 않습니다.
- 현재 브라우저의 서버 쿠키를 기준으로 하며 비밀번호·인증 토큰·로그인 상태를 localStorage/sessionStorage에 저장하지 않습니다.
