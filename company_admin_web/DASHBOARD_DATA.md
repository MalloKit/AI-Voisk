# 대시보드 실데이터 통합 (2026-10-27)

기준: 60ff69b. 기존 Repository·파서·useAsync·GET 계약을 그대로 사용합니다.
서버, DB, 인증, 패키지, 환경변수 설정은 변경하지 않습니다.

## 데이터와 상태
| 표시 | 실제 모드 | 명시적 Mock 모드 |
| --- | --- | --- |
| 등록 매장 | 전체 매장 API 결과 길이 | Mock 매장 수 |
| 점주 계정 | 전체 점주 API 결과 길이 | Mock 점주 수 |
| 점주 미연결 매장 | 실제 매장의 ownerId === null 건수 | Mock 매장의 미연결 건수 |
| 최근 7일 주문 | 기존 실제 주문 목록·기간 계산 유지 | 기존 Mock 주문 |
| 기기·오프라인·미확인 알림 | Mock 유지 | Mock 유지 |

기존 파서가 전체 응답 건수를 검증한 결과를 재사용하므로 DB 예시 숫자를 하드코딩하지 않습니다.
API 로딩은 조회 중, 실패는 조회 실패, 성공한 빈 배열은 0곳/0개로 표시합니다.
이전 성공 데이터가 남아 있어도 재조회 실패 시 그 건수나 목록을 성공 결과처럼 표시하지 않습니다.

## 공유와 새로고침
- App에서 주문·매장·점주 목록을 각각 useAsync로 관리합니다. 각 로더는 해당 Repository만 의존합니다.
- 최초 앱 진입에 각 실제 목록을 조회하고, 대시보드와 관리 화면은 동일한 결과를 받습니다.
- 화면 이동·상세 열기만으로 목록을 다시 조회하지 않습니다. 상세는 기존 별도 상세 API를 호출합니다.
- 대시보드 매장 새로고침과 관리 화면 새로고침은 같은 매장 상태를 갱신합니다. 미연결 수·목록도 함께 바뀝니다.
- 점주 새로고침은 점주 지표·계정 목록만 갱신합니다. 매장과 주문은 재조회하지 않습니다.
- 기존 주문 새로고침과 공유 결과는 유지합니다.
- 출처별 실패는 다른 출처를 실패 처리하지 않습니다. 매장/점주 다시 시도 버튼도 독립적입니다.
- 미연결 매장 바로가기는 같은 실제 목록에 미연결 필터를 적용합니다.
- 대시보드 실제 매장 모달은 기존 LiveStoreDetail을 재사용합니다. 같은 ID의 Mock 매장/관리자를 결합하지 않습니다.
- 각 source=mock 설정은 해당 출처에만 적용합니다. 실제 API 실패에 따른 Mock 전환은 없습니다.

기존 사용자가 확인한 Vitest 52개·FastAPI 39개·빌드 성공을 이번 변경 후의 통과 결과로 간주하지 않습니다.
Vitest의 scripts/store-contract.test.mjs 제외 설정은 변경하지 않았습니다.
실제 Azure DB에 접속하거나 데이터를 변경하지 않았습니다.

## 노트북 검증
1. npm test로 총 63개 테스트와 Node 테스트 수집 제외를 확인합니다.
2. npm run build로 TypeScript 검사와 Vite 빌드를 확인합니다.
3. server에서 python -m unittest discover -p "test_*.py" -v로 기존 서버 전체 검증을 실행합니다.
4. 로컬 FastAPI를 실행하고 읽기 전용으로 실제 목록과 지표가 맞는지 확인합니다. 매장 1·점주 0 같은 예시 숫자를 기준으로 삼지 않습니다.
5. 매장·점주·주문 화면을 오가며 브라우저 Network에서 각 목록이 최초 한 번만 호출되는지 확인합니다.
6. 대시보드와 각 관리 화면에서 새로고침하고 공유 지표·목록 반영을 양방향 확인합니다.
7. 각 API 요청만 차단해 다른 출처의 정상값 유지, 조회 실패·재시도·0건 구분을 확인합니다.
8. 미연결 바로가기·실제 상세·모달 Escape·검색/필터와 명시적 Mock 모드를 확인합니다.
9. 기기·알림이 계속 Mock으로 표시되고 기존 확인 처리 동작이 유지되는지 확인합니다.
