# AI-Voisk 회사 관리자 웹

React + TypeScript + Vite 기반 회사 관리자 웹입니다. 같은 폴더의 기존 Flutter 관리자 앱을 대체했습니다. 키오스크·FastAPI·Azure MySQL·점주용 프로젝트는 전환 대상이 아닙니다.

## 실행

Node.js 22.12 이상과 npm이 필요합니다. Node 24.19.0에서 검증했습니다. 회사 관리자 폴더에서 실행합니다.

```powershell
npm install
npm run dev
```

브라우저: **http://127.0.0.1:8080** (또는 http://localhost:8080). 기존 FastAPI를 **http://127.0.0.1:8001**에서 별도로 실행해야 실제 주문이 조회됩니다. 서버 실행은 기존 서버 안내를 따릅니다. 이 앱은 DB에 직접 접속하지 않습니다.

개발/미리보기 포트는 8080으로 고정되며 이미 사용 중이면 종료합니다. 기존 FastAPI의 CORS 허용 주소와 일치하므로 서버나 프록시를 수정하지 않았습니다.

```powershell
npm run build       # TypeScript 검사 + dist 생성
npm run preview     # localhost:8080 (dev와 동시 실행하지 않음)
npm test            # 실제 DB 없는 자동 검증
npm run test:live   # 로컬 FastAPI 실행 시 GET 목록/상세/CORS 읽기 전용 검증
```

이 PC에는 npm이 PATH에 없어 `.tools/` 안에 공식 npm 패키지를 임시 준비했습니다. 이 도구는 Git에 포함되지 않으며 앱 의존성이 아닙니다. 일반 환경에는 npm이 포함된 Node.js 배포판을 설치하면 위 명령을 사용합니다. 현재 PC의 준비된 도구를 사용하려면 현재 PowerShell 세션에만 다음 경로를 추가합니다.

```powershell
$env:PATH = (Join-Path (Get-Location) '.tools') + ';' + $env:PATH
npm install
npm run dev
```

## 데이터 출처

- **주문 조회**: 기본적으로 실제 FastAPI를 호출합니다. GET만 사용하며 저장·결제 API를 호출하지 않습니다.
- **운영 요약**: 주문 지표와 최근 주문은 주문 조회와 공유하는 동일한 실제 FastAPI 주문 목록을 사용합니다. 화면 이동 시 중복 조회하지 않으며 어느 화면에서 새로고침해도 결과가 공유됩니다. 상세는 동일한 상세 API를 호출합니다. 매장·점주 지표도 각 관리 화면과 공유하는 실제 조회 결과를 사용합니다. 출처별 새로고침과 로딩·오류·0건 상태는 독립적입니다. 기기·알림만 기존 Mock을 유지합니다. 명시적 Mock 주문 모드에서는 대시보드의 주문도 Mock입니다.
- **매장 관리**: 실제 관리자 매장 API로 목록·상세를 조회합니다. 검색·필터는 조회한 전체 매장에 적용하며 실패 시 Mock으로 대체하지 않습니다.
- **점주 계정**: 실제 점주 API로 계정·연결 매장 수·연결 매장 상세를 조회합니다. 실제 점주와 Mock 매장을 결합하지 않습니다.
- **기기 관리**: 실제 기기 API로 등록 정보·활성화 상태를 조회합니다. 접속 상태는 미확인입니다. 대시보드 기기 요약은 Mock으로 유지합니다.
- **장애/알림**: 실제 알림 API로 목록·상세만 조회합니다. 원본 유형·심각도·상태를 보존하고 확인·해소 기록을 구분합니다. 실제 확인 처리는 제공하지 않습니다. 대시보드 알림 요약은 Mock입니다.
- 명시적 Mock 알림 모드에서만 기존 메모리 확인 처리를 제공합니다. 화면 이동 시 유지되지만 브라우저 새로고침하면 초기화됩니다. 실제 알림과 연결하지 않습니다.
- API 오류를 Mock 데이터로 대체하지 않습니다. 대시보드도 실제 주문 조회 실패 시 실패 상태와 재시도 버튼을 표시하며 가짜 주문 건수를 보여주지 않습니다.

공개 설정은 `.env.example`을 참고하세요. 주소를 변경하려면 개인 `.env.local`에 `VITE_ORDER_API_BASE_URL`을 지정하고 개발 서버를 재시작합니다. **VITE\_ 값은 브라우저에 포함되므로 비밀번호·DB 설정·인증 비밀을 넣지 마세요.**

Mock 주문 확인은 `VITE_ORDER_SOURCE=mock`을 명시합니다. 기본값은 `api`이며 주소를 생략해도 자동으로 Mock 전환하지 않습니다.

## 주문 API

```text
GET /admin/orders?limit=200&offset=0
GET /admin/orders/{order_id}
```

목록의 `orders`/`total`을 읽고 기존 Flutter처럼 모든 페이지를 조회한 뒤 화면 필터를 적용합니다. 주문 유형(포장/매장 식사/미확인), 기기 ID(미확인 포함), 직접 선택한 날짜 범위 필터를 지원합니다. 날짜는 브라우저 현지 날짜 기준이며 양 끝 날짜를 포함합니다. 한쪽 날짜만 지정할 수도 있습니다. 상세의 메뉴·수량·옵션과 주문 유형을 표시합니다. 날짜는 API 오프셋을 해석하여 브라우저 현지 시각으로 표시합니다.

명시적 `order_type=takeaway|dine_in`을 우선합니다. 이전 응답에 유형이 없으면 `table_no=0`은 포장, 양수는 매장 식사로 해석합니다. NULL 테이블 신규 주문에는 번호를 표시하지 않고 불명확한 유형은 미확인으로 표시합니다. 주문 당시 가격이 없으므로 과거 금액을 만들어 표시하지 않습니다.

요청 타임아웃 20초. 상세 요청은 모달을 닫으면 취소됩니다. 공유 목록은 화면 이동 시 유지하며 재조회·앱 종료 시 이전 요청을 취소합니다. 정식 관리자 인증이 없는 기존 API이므로 로컬 시연으로 사용하며 외부 배포하지 않습니다.

  data/
    models.ts / selectors.ts
    adminRepository.ts       # Mock 관리 Repository
    orderRepository.ts       # 실제 GET 주문 Repository
    mock/admin-fixture.json  # 등록 정보/주문 샘플

## 매장 관리 API 전환
매장 관리는 기본적으로 실제 관리자 매장 API를 읽습니다. 대시보드의 매장 지표·미연결 목록은 같은 조회 결과를 공유하며 화면에 출처를 표시합니다.
등록·수정·점주 연결은 인증/권한 체계 도입 전까지 제공하지 않습니다.
계약·데이터 출처·추가 조건·검증 방법: [STORE_API.md](STORE_API.md).


## 점주 계정 API 전환
기본적으로 실제 읽기 전용 API를 사용합니다. 대시보드의 점주 수도 같은 조회 결과를 공유하며 카드에 출처를 표시합니다.
계정 생성·삭제·비밀번호 변경·매장 연결 변경은 제공하지 않습니다.
API 계약·추가 설계 조건·이번 검증 결과: [OWNER_API.md](OWNER_API.md).

## 대시보드 조회 통합
실제 매장·점주·주문 목록을 App에서 독립적으로 관리합니다. 목록 새로고침은 출처별로 수행하며 화면 이동만으로 다시 호출하지 않습니다.
동작·테스트·노트북 확인 항목: [DASHBOARD_DATA.md](DASHBOARD_DATA.md).

## 기기 조회 API 전환
기기 목록·상세는 기본 실제 API이며 등록·수정·활성화 변경은 제공하지 않습니다.
계약·NULL·시간대 정책·검증 결과: [DEVICE_API.md](DEVICE_API.md).

## 장애·알림 조회 API 전환
실제 목록·상세는 device_alert와 기기·매장 JOIN을 사용하며 관리자 확인·해소·생성 API는 추가하지 않았습니다.
원본 값·시간대 정책·전체 검증·페이지 처리 확장안: [ALERT_API.md](ALERT_API.md).
