# 카카오페이 개발용 결제 테스트

운영 결제는 지원하지 않습니다. CID는 `TC0ONETIME`만 허용합니다.
개발용 키는 개인 `server/.env`에만 저장하고 Git·앱·화면에 포함하지 않습니다.

```dotenv
KAKAOPAY_SECRET_KEY=개발자센터에서_발급받은_Secret_key_dev
KAKAOPAY_CID=TC0ONETIME
```

카카오페이 앱의 플랫폼 > Web 사이트 도메인에 `http://localhost:8001`을 등록합니다.
로그인 API용 Redirect URL과 결제의 approval/cancel/fail URL은 별개입니다.
현재 콜백 주소는 서버가 위 localhost 도메인 아래에서 생성합니다.

## 실행

API를 종료한 뒤 다시 시작합니다. worker는 1개로 실행합니다.

```powershell
cd C:\AI-Voisk\server
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8001 --no-access-log
```

Flutter 기존 실행을 종료하고 개발용 연결 옵션으로 다시 실행합니다.

```powershell
cd C:\AI-Voisk\kiosk_app
flutter run -t lib/main_preview.dart --dart-define=MENU_API_BASE_URL=http://10.0.2.2:8001 --dart-define=ORDER_API_BASE_URL=http://10.0.2.2:8001 --dart-define=STORE_ID=1 --dart-define=DEVICE_ID=1 --dart-define=KAKAOPAY_TEST=true
```

1. 실제 DB 메뉴를 담고 결제하기 > 카카오페이를 선택합니다. 자동으로 테스트 결제를 준비합니다.
2. 서버는 활성 기기·판매 중인 메뉴·옵션을 읽기 전용 트랜잭션에서 검증하고 총액을 계산합니다.
3. 키오스크 내부 WebView에서 카카오페이 공식 PC 결제창의 QR을 표시합니다. 고객 계정으로 공용 태블릿에 로그인하지 않고, 고객 휴대폰으로 QR을 스캔합니다.
4. 휴대폰에서 개발용 결제를 인증하고, 키오스크의 공식 결제창에 확인 버튼이 나오면 누릅니다.
5. WebView는 등록된 localhost 콜백을 가로채 같은 세션의 승인·취소·실패 경로만 로컬 API 주소로 전달합니다. 서버가 승인 API를 호출하고 금액·TID·주문번호 등을 검증합니다.
6. 앱은 2초 간격으로 서버 결과를 조회하고, 승인 검증 성공 시 완료 화면을 표시합니다.

공식 데모가 `카톡 결제`를 지원하지 않는다고 표시하는 경우 이를 활성화하지 않습니다. QR 결제로 검증합니다.
QR 인증 중에는 왼쪽에 주문 내역과 총액을 유지하고 오른쪽에 공식 결제창을 표시합니다. Android WebView의 늘어나는 오버스크롤 효과를 비활성화합니다. 공식 페이지가 화면보다 길면 정상적인 내부 스크롤은 유지합니다.

처음 WebView 플러그인 추가 후에는 hot reload가 아니라 Flutter를 종료하고 위 명령으로 다시 빌드·실행해야 합니다.
기존 서버 응답에 checkout_url이 없는 경우에는 PC 결제 주소 복사 방식이 남아 있으므로 서버도 재시작합니다.

기본 설정은 승인 흐름만 시연합니다. `payments` 테이블이 준비된 DB에서 테스트 주문 저장을 사용하려면 API 실행 전 같은 PowerShell에서 `$env:KAKAOPAY_SAVE_TEST_ORDERS = '1'`을 실행합니다. 승인된 주문·메뉴·옵션·결제 기록을 함께 저장하며, 결제 기록에는 `is_test = TRUE`를 기록합니다. 완료 화면에 테스트 주문번호가 표시됩니다. 저장 오류가 나면 서버를 켜 둔 채 앱의 `주문 저장 다시 시도`를 누릅니다.
기타 결제 수단은 기존 화면 시연입니다. `KAKAOPAY_TEST`를 생략하면 카카오페이도 기존 시연입니다.

## 제한사항

- 로컬 PC·Android 에뮬레이터 테스트 전용입니다. 휴대폰은 카카오페이 QR 주소를 열며, localhost 콜백을 직접 열지 않습니다.
- 서버를 공인 주소나 터널로 노출하지 않습니다. 실제 태블릿·고객 휴대폰용 결제 구조와 인증은 별도 구현해야 합니다.
- 결제 대기는 서버 기준 15분 뒤 만료되며, 앱에서 장바구니를 유지한 채 다시 시도할 수 있습니다. 취소·실패·만료 뒤 재시도는 새 요청 ID를 사용합니다.
- QR 위의 남은 시간은 서버 응답의 `expires_in`을 기준으로 감소하며 색상은 바뀌지 않습니다. 0초에서는 QR을 가리고 서버의 만료 결과를 확인한 뒤 재시도를 허용합니다. 서버 연결 실패를 만료나 승인으로 간주하지 않습니다.
- 승인 완료·결과 불명 상태는 시간만으로 만료시키지 않습니다. 결과 불명 또는 서버 재시작으로 세션을 찾지 못하는 경우에는 개발자센터에서 결과를 확인해야 합니다. 서버 메모리만 사용하며 운영 결제의 영속 저장·정산·복구 기능이 아닙니다.
- 승인 통신 실패·응답 불일치는 `unknown`으로 표시하고 다시 승인하지 않습니다. 성공으로 추측하거나 새 결제를 반복하지 말고 개발자센터에서 확인합니다.
- 대기 취소는 승인 전 로컬 테스트를 중단합니다. 이미 승인된 거래를 환불하는 기능이 아닙니다.
- 실제 API를 호출한 통합 테스트는 개발용 설정과 사용자 인증이 준비된 후 사람이 진행합니다. 자동 테스트는 카카오페이·공용 DB에 접속하지 않습니다.
