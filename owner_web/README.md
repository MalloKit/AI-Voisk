# AI-Voisk 점주 관리자 웹

React + TypeScript + Vite 기반 점주 관리자 웹입니다. 회사 관리자 웹(`company_admin_web`)과 같은 스택을 쓰지만 코드를 import하지 않고 필요한 테마·공통 컴포넌트를 복사해 독립적으로 동작합니다.

## 실행

Node.js 22.12 이상과 npm이 필요합니다.

```powershell
cd owner_web
npm install
npm run dev
```

브라우저: **http://127.0.0.1:8081**. 8080은 회사 관리자 웹이 쓰므로 8081에 고정했고, 이미 사용 중이면 종료합니다.

```powershell
npm run build   # TypeScript 검사 + dist 생성
npm run preview # 127.0.0.1:8081 (dev와 동시 실행하지 않음)
npm test        # 실제 서버·DB 없는 자동 검증
```

## 데이터 출처

- 지금은 모든 화면이 **시연 데이터(Mock)** 입니다. 서버에 점주용 API가 아직 없어서 서버와 DB에 접속하지 않습니다.
- 화면은 `OwnerRepository` 인터페이스만 사용합니다. 실제 API가 생기면 구현체를 만들어 `App.tsx`의 기본 Repository 한 곳만 바꿉니다.
- `MockOwnerRepository`는 메모리에만 저장합니다. 새로고침하면 처음 상태로 돌아갑니다.
- 메뉴·옵션은 `server/seed_test_menus.sql`, `server/seed_test_options.sql`의 T0001 매장과 같습니다. id 값은 공용 DB와 무관한 Mock 값이고, 시드에는 없는 점주 연결(`ownerId`)을 Mock에서 붙였습니다.
- 주문은 시연 기준 시각(`src/data/demoClock.ts`의 `DEMO_NOW`, 2026-10-29 12:00 한국 시간) 전 30일 동안 20건이고, 그중 4건이 오늘 주문입니다. 서버와 같이 `order_type`은 `takeaway` | `dine_in`, 신규 주문처럼 `table_no`는 NULL이며 한 품목에 옵션 여러 개(`order_item_option`)를 둡니다.
- '오늘'은 브라우저 시간대가 아니라 매장 시간대(Asia/Seoul) 기준입니다.
- 키오스크 연결 상태(`connection`, `lastSeenAt`)는 아직 DB에 없는 Mock 계약입니다.
- 로그인은 아래 [점주 로그인](#점주-로그인)을 보세요. 서버에 점주 인증 API가 없어 지금은 Mock 인증으로 동작합니다.

## 점주 로그인

- 진입점은 `AppEntry`입니다. 처음 열면 `me`로 로그인 여부를 확인하고, 로그인하지 않았으면 로그인 화면만 보여 줍니다.
- 로그인 ID(소문자 영문·숫자·`.`·`_`·`-` 4~100자)와 비밀번호(8~128자) 형식을 먼저 검사합니다. 정책은 `feature/company-admin-v2`의 `company_admin_web/OWNER_WRITES.md`와 같습니다(`src/data/ownerAuth.ts`).
- 실패 문구는 ID가 틀렸는지 비밀번호가 틀렸는지 구분하지 않습니다: "로그인 ID 또는 비밀번호가 올바르지 않습니다."
- 로그인 후 연결된 매장이 1개면 바로 들어가고, 여러 개면 매장 선택 화면, 0개면 "연결된 매장이 없습니다. 회사 관리자에게 문의해 주세요."를 보여 줍니다. 열 수 있는 매장은 `me`가 돌려준 목록뿐입니다.
- 사이드바 아래에 로그인 ID와 로그아웃, 매장이 여러 개면 매장 바꾸기가 있습니다. 메뉴 관리에 저장 안 한 변경이 있으면 로그아웃·매장 바꾸기 전에도 [계속 편집] [버리고 …] [저장하고 …]를 묻습니다.
- 60초마다, 그리고 창으로 돌아올 때 `me`로 세션을 다시 확인합니다. 401이면 로그인 화면으로 보내고 "로그인이 만료되었습니다. 다시 로그인해 주세요."를 보여 줍니다. 점주 데이터 API를 붙일 때 401을 받으면 `notifySessionExpired()`(이벤트 `voisk:owner-session-expired`)를 호출하면 같은 처리가 됩니다.
- 비밀번호·토큰·로그인 상태를 localStorage·sessionStorage에 저장하지 않습니다. 비밀번호 입력칸은 제출 뒤 비웁니다.
- 화면은 `OwnerAuthRepository`만 씁니다. 인증 출처는 `.env.local`의 `VITE_OWNER_AUTH_SOURCE`로 고릅니다(`.env.example` 참고).

| 값            | 구현체                    | 설명                                                                                                                                        |
| ------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `mock` (기본) | `MockOwnerAuthRepository` | 개발용 Mock 계정. 세션이 메모리에만 있어 새로고침하면 로그아웃됩니다.                                                                       |
| `api`         | `ApiOwnerAuthRepository`  | 아래 서버 API를 `VITE_OWNER_API_BASE_URL`(기본 `http://127.0.0.1:8001`)로 호출합니다. 서버 API가 아직 없어 실제 연결은 검증하지 않았습니다. |

메뉴·주문 데이터는 점주용 서버 API가 없어 두 경우 모두 매장별 `MockOwnerRepository`를 씁니다.

### 개발용 Mock 계정

**실제 운영 계정이 아닙니다.** `mock` 모드에서만 로그인되고, 로그인 화면에도 "개발용 Mock 계정"으로 표시합니다. 운영 DB에 이 값을 넣지 않습니다. 정의는 `src/data/mock/mockOwnerAccounts.ts`입니다.

| 로그인 ID     | 비밀번호             | 연결 매장                                                          |
| ------------- | -------------------- | ------------------------------------------------------------------ |
| `mock.single` | `mock-only-password` | 매장 1 보이스크 테스트 매장(T0001, 시드와 같은 메뉴)               |
| `mock.multi`  | `mock-only-password` | 매장 2 보이스크 Mock 카페(T0002), 매장 3 보이스크 Mock 분식(T0003) |

`store.owner_id`는 매장마다 점주 한 명이라 매장 2·3은 이 계정을 위한 작은 Mock 매장입니다.

## 서버에 필요한 점주 인증 API

회사 관리자 인증(`feature/company-admin-v2`의 `server/AUTH.md`)과 같은 방식을 가정합니다. 세션은 서버 메모리 + HttpOnly 쿠키, 브라우저는 `credentials: "include"`로 요청합니다. **서버에는 아직 없습니다.** 클라이언트 구현은 `src/data/ownerAuthRepository.ts`의 `ApiOwnerAuthRepository`입니다.

| 메서드 | 경로                 | 요청                                                                    | 성공 응답                                                          |
| ------ | -------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------ |
| GET    | `/auth/owner/csrf`   | 없음                                                                    | `200 { "csrf_token": "…" }` (익명 세션 또는 현재 세션에 묶인 토큰) |
| POST   | `/auth/owner/login`  | 헤더 `X-CSRF-Token`, 본문 `{ "login_id": "…", "password": "…" }`만 허용 | `200` 아래 점주 객체. 세션·CSRF를 새로 발급                        |
| GET    | `/auth/owner/me`     | 세션 쿠키                                                               | `200` 아래 점주 객체                                               |
| POST   | `/auth/owner/logout` | 헤더 `X-CSRF-Token`(로그아웃 직전에 csrf를 다시 받음)                   | `204`, 세션 폐기·쿠키 삭제                                         |

login·me의 점주 객체:

```json
{
  "owner": {
    "owner_id": 1,
    "login_id": "kim.owner",
    "role": "owner",
    "stores": [{ "store_id": 1, "store_name": "보이스크 테스트 매장" }]
  }
}
```

- `stores`는 `store.owner_id = owner_id`인 매장입니다. 없으면 빈 배열입니다. 비밀번호 해시·세션 ID는 응답에 넣지 않습니다.
- 클라이언트는 `role`이 `"owner"`일 때만 받아들입니다.

오류 응답(클라이언트가 보여 주는 문구):

| 상태    | 경우                                                               | 화면 문구                                                               |
| ------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| 401     | 로그인 실패(없는 ID·틀린 비밀번호를 구분하지 않음), 세션 없음·만료 | "로그인 ID 또는 비밀번호가 올바르지 않습니다." / 만료면 로그인 화면으로 |
| 403     | Origin·CSRF·역할 오류                                              | "인증 요청을 확인할 수 없습니다…"                                       |
| 413·422 | 입력 형식·길이                                                     | "로그인 입력 형식과 길이를 확인해 주세요."                              |
| 429     | 로그인 시도 제한                                                   | "로그인 시도가 많습니다. 잠시 후 다시 시도해 주세요."                   |
| 그 밖   | 서버·DB 오류                                                       | "인증 서버에 연결하지 못했습니다…"                                      |

### 권한 조건

- **점주는 자기 매장만 조회·수정할 수 있어야 합니다.** 점주 업무 API(메뉴 조회·저장, 품절, 주문 조회, 매장 정보 등)는 요청마다 세션의 `owner_id`와 대상 매장의 `store.owner_id`가 같은지 서버에서 확인해야 합니다. 화면의 매장 목록이나 요청에 들어 있는 `store_id`를 그대로 믿으면 안 됩니다.
- 메뉴·옵션·카테고리·주문을 id로 바꾸거나 읽을 때도 그 행이 속한 매장(`category.store_id`, `orders.store_id`)이 점주의 매장인지 확인합니다. 다른 매장 것이면 403 또는 404입니다.
- 점주 세션은 회사 관리자 세션과 분리합니다. 점주 세션으로 `/admin/*`을 쓸 수 없고, 반대도 마찬가지입니다. 클라이언트가 보낸 역할은 받지 않습니다.
- 매장 연결이 바뀌면(회사 관리자가 `store.owner_id` 변경) 다음 요청부터 바로 반영되어야 합니다. 클라이언트도 60초마다·창 복귀 때 `me`를 다시 읽고, 열려 있던 매장이 목록에서 빠지면 매장 선택 화면으로 돌아갑니다.
- 비밀번호는 `owner.own_pw`의 Argon2id 해시로만 검증하고, 실패 응답·로그에 입력값을 남기지 않습니다. 계정 정책(ID 4~100자 소문자 등, 비밀번호 8~128자)은 OWNER_WRITES.md와 같아야 합니다.
- 상태를 바꾸는 요청(POST·PATCH 등)은 Origin과 `X-CSRF-Token`을 함께 확인하고, 모든 인증·점주 응답은 `Cache-Control: no-store`로 보냅니다.

## 메뉴 관리

- 왼쪽(약 40%)은 '＋ 새 메뉴' 칩, 편집 패널, '숨긴 메뉴' 상자이고 오른쪽(약 60%)은 태블릿 미리보기입니다. 1150px보다 좁으면 미리보기를 위에 두고 위아래로 쌓습니다.
- 미리보기는 `kiosk_app/lib/service/screens/order_screen.dart`를 1280×800 논리 픽셀로 그린 뒤 폭에 맞춰 줄인 것입니다. 서버 `GET /stores/{id}/menus`와 같이 `is_active` 메뉴만 `category_sort, category_id, menu_sort, menu_id` 순서로 보여 줍니다. 아이콘은 Material 대신 비슷한 lucide 아이콘이라 실제 화면과 조금 다릅니다.
- 판매 중인 메뉴가 없는 카테고리는 실제 키오스크에 보이지 않습니다. 미리보기에서는 편집할 수 있게 흐리게 표시합니다. 점선 ＋ 버튼, 주황 점, 놓일 위치 선은 편집용 표시입니다.

### 드래그 (`@dnd-kit/core`)

| 끄는 것    | 놓는 곳                 | 결과                                                                      |
| ---------- | ----------------------- | ------------------------------------------------------------------------- |
| 메뉴 카드  | 다른 카드의 앞·뒤       | 그 자리로 이동 (다른 카테고리 카드면 카테고리도 이동)                     |
| 메뉴 카드  | 레일의 카테고리         | 그 카테고리 맨 뒤로 이동                                                  |
| 메뉴 카드  | 숨긴 메뉴 상자          | 판매 중지 (`is_active = FALSE`)                                           |
| 숨긴 메뉴  | 카드·카테고리·메뉴 영역 | 그 자리에서 다시 판매                                                     |
| ＋ 새 메뉴 | 카드·카테고리·메뉴 영역 | 그 자리에 이름·가격이 빈 새 메뉴 (누르기만 하면 보고 있는 카테고리 맨 뒤) |
| 카테고리   | 다른 카테고리의 위·아래 | 카테고리 순서 변경                                                        |

- 마우스는 6px 넘게 움직여야, 터치는 0.2초 눌러야 드래그가 됩니다. 그보다 작으면 클릭(선택)이라 터치 스크롤과 겹치지 않습니다.
- 키보드: 카드나 카테고리에서 Space로 집고, 화살표로 가장 가까운 놓을 곳으로 옮긴 뒤, Space나 Enter로 놓습니다. Esc는 취소입니다. 키보드로 카드에 놓으면 그 카드 앞에 들어갑니다(맨 뒤로 보내려면 카테고리에 놓습니다).
- 놓기 결과는 `features/menus/dnd.ts`의 `resolveDrop` 순수 함수가 정합니다. jsdom에서는 요소 크기가 0이라 실제 끌기는 자동 테스트하지 못하고, 이 함수를 테스트합니다.

### 저장

- **품절**(메뉴·저장된 옵션)만 누르는 즉시 Repository에 반영합니다. 나머지 변경(순서, 카테고리 이동, 숨기기, 새 메뉴, 이름·가격·설명, 옵션, 카테고리 추가·이름·삭제)은 초안에 모았다가 화면 아래 저장 바에서 한 번에 저장합니다.
- 저장을 누르면 "콜라: 음료 → 식사 이동", "만두 숨김", "식사 메뉴 순서 변경" 같은 변경 목록을 보여 주고 확인을 받습니다. 저장 안 된 변경 건수도 이 목록으로 셉니다.
- 이름이나 가격이 빈 메뉴, 이름이 비거나 겹치는 카테고리가 있으면 저장을 막고 그 항목을 선택해 입력칸으로 보냅니다.
- 변경 취소는 마지막 저장 상태로 돌리고, 되돌리기(버튼, 입력칸 밖에서 Ctrl+Z)는 한 단계씩 돌립니다. 둘 다 이미 반영한 품절은 건드리지 않습니다. 같은 입력칸을 이어서 고친 것은 한 단계로 묶습니다.
- 저장하지 않고 다른 화면으로 가면 [계속 편집] [버리고 이동] [저장하고 이동]을 묻고, 새로고침·탭 닫기에는 브라우저 경고를 띄웁니다.
- 저장은 `OwnerRepository.saveMenuBoard(changes)` 한 번입니다. `changes`(`MenuBoardChanges`)는 카테고리·메뉴·옵션의 create/update(카테고리는 remove 포함) 묶음이고, 새 항목은 음수 임시 id로 서로를 가리킵니다. `category_sort`, 카테고리별 `menu_sort`, 메뉴별 `menu_option_sort`는 1부터 빈틈없이 다시 매겨 보냅니다. 서버는 이 묶음을 한 트랜잭션으로 처리하고, 결과로 전체 메뉴판과 임시 id → 실제 id 대응표를 돌려줍니다. Mock도 하나라도 실패하면 아무것도 바꾸지 않습니다.
- 메뉴가 남은 카테고리는 삭제할 수 없습니다(숨긴 메뉴 포함). DB FK에 ON DELETE 규칙이 없어 실제로도 거부됩니다. 저장된 옵션 삭제는 주문 기록을 지키기 위해 판매 중지(`is_active = FALSE`)로 처리합니다.

## 오늘 현황 · 주문 내역 · 매장 정보

- **오늘 현황**: 오늘 주문 수(포장·매장 식사), 오늘 매출(어제 매출 함께), 품절 메뉴 수(있으면 빨간 강조, 누르면 메뉴 관리), 판매 중지 메뉴 수, 키오스크 연결 상태(끊기면 빨간 강조), 지금 품절인 메뉴·옵션과 [판매 재개](즉시 반영), 오늘 많이 팔린 메뉴 TOP 5, 최근 주문 5건.
- **주문 내역**(조회 전용): 기간(오늘·최근 7일·최근 30일·전체, 기본 최근 7일), 구분(전체·매장 식사·포장), 주문번호 검색. 건수와 합계를 보여 주고, 행이나 주문번호를 누르면 품목·수량·옵션·추가 금액·합계 상세가 열립니다.
- **매장 정보**(조회 전용): 매장 이름, 업종, 매장 코드, 대표자, 전화번호, 사업자등록번호(000-00-00000), 주소. 변경은 회사 관리자에게 요청한다는 안내와 키오스크가 이 store_id로 메뉴를 불러온다는 안내가 있습니다.
- `order_item`에 주문 당시 가격이 없어 금액은 **현재 메뉴·옵션 가격**으로 계산합니다. 메뉴 가격을 바꾸면 지난 주문 금액도 바뀌므로 화면에 "현재 메뉴 가격 기준"을 표시합니다. 정확한 매출이 필요하면 주문 시 가격을 저장하도록 DB를 바꿔야 합니다.
- 옵션은 `order_item_option`과 이전 단일 옵션(`order_item.option_id`)을 합쳐 보여 줍니다. 주문 유형은 `order_type`을 우선하고, 없으면 `table_no`(0 포장, 양수 매장 식사)로 해석합니다.
- 서버 시각(UTC)은 한국 시간(Asia/Seoul)으로 바꿔 보여 주고, '오늘'과 기간도 한국 날짜로 셉니다. 기준 시각은 `App`의 `now`(기본 `DEMO_NOW`)입니다.

## 색 규칙

- 사이드바와 바탕은 흰색과 밝은 회색입니다. 초록(`--brand`)은 주요 버튼, 선택된 메뉴, 강조 표시에만 씁니다.
- 상태 색은 따로 씁니다. 오류·연결 끊김은 빨강(`--error`), 저장하지 않은 변경은 주황(`--unsaved`), 정상은 연한 초록(`--ok`)입니다.
- 키오스크 미리보기는 `--kiosk-*` 토큰만 씁니다(`kiosk_app/lib/service/screens/order_screen.dart`의 색). 관리자 화면 색과 섞지 않습니다. 편집용 표시(선택된 카드 테두리, 점선 ＋ 버튼)만 예외입니다.
