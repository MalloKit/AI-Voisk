# 직접 구현한 시작 화면과 고객 서비스 안내

이 문서는 이번 작업에서 추가한 역할 선택 화면과 고객 서비스 화면만 설명합니다.
팀 공통 프로젝트 구조, DB 설계, 관리자·점주 구현은 이 문서의 범위에 포함하지 않습니다.

## 작업물 구성

```text
kiosk_app/
├─ lib/
│  ├─ main_preview.dart          # 역할 선택 화면 확인용 실행 파일 (신규)
│  ├─ home/
│  │  ├─ role_select_screen.dart # 관리자·점주·고객 서비스 선택 화면
│  │  ├─ tests/role_select_test.dart
│  │  └─ README.md              # 작업물 안내
│  └─ service/                  # 고객 주문 기능
│     ├─ models/                # 메뉴와 추가 옵션 정보
│     ├─ data/                  # 임시 메뉴 공급
│     ├─ controllers/           # 장바구니와 금액 계산
│     ├─ screens/               # 주문 화면과 선택 창
│     ├─ tests/                 # 편집·알림·버튼 반응 검사
│     └─ README.md              # 고객 서비스 상세 안내
└─ test/widget_test.dart        # 기존 예제 테스트를 주문 검사로 교체
```

첫 주문 화면 실행 연결 작업에서 기존 lib/main.dart를 수정했습니다.
역할 선택 화면을 추가할 때는 main.dart와 서비스 코드를 추가로 수정하지 않았습니다.
현재 main.dart는 주문 화면, main_preview.dart는 역할 선택 화면을 실행합니다.

## 고객 서비스 구현 요약

- 카테고리별 메뉴 카드와 수량·추가 옵션 선택
- 장바구니 담기, 수량 변경, 삭제, 합계 표시
- 장바구니 항목을 눌러 옵션 수정, 변경 저장·취소
- 같은 메뉴·옵션 조합의 수량 합산, 다른 조합 분리
- 가운데 담기·수정 완료 알림과 2.5초 후 자동 닫기
- 직원 호출 안내 창과 닫기 버튼, 2.5초 후 자동 닫기
- Language 선택 창: 한국어·日本語·English·中文
- 직원 호출·마이크·주문내역·결제하기 버튼의 누름 색상 효과
- 목록 끝에서 늘어나는 효과 제거, 스크롤 유지

메뉴는 임시 데이터 7개이며 음식 그림은 임시 아이콘입니다.
서버·DB·음성·실제 결제·실제 직원 알림·주문내역 조회·번역은 연결하지 않았습니다.
장바구니는 앱 실행 중에만 유지되며 다시 시작하면 초기화됩니다.
옵션 가격, 파일별 역할, 직접 확인 항목은 [서비스 상세 안내](../service/README.md)에 있습니다.

## 역할 선택 화면

화면 중앙에 관리자·점주·고객 서비스 버튼 3개만 표시합니다.
각 버튼은 180×80의 논리 화면 크기로 만들었으며 가로 공간이 충분하면
나란히 표시하고 좁으면 줄바꿈합니다. 제목·아이콘·설명 카드는 제거했습니다.

팀 통합·시연용으로 관리자 / 점주 / 고객 서비스를 선택하는 시작 화면입니다.
관리자·점주는 준비 중 안내만 표시합니다. 고객 서비스는 기존 주문 화면으로
이동하며 뒤로 가면 선택 화면으로 돌아옵니다.

기존 main.dart와 서비스 코드를 수정하지 않고 main_preview.dart를 통해
별도로 실행합니다. 아직 공통 앱 시작 화면으로 연결하지 않았습니다.

## 실행

1. Android 가상 태블릿을 켜고 가로로 회전합니다.
2. VS Code → 터미널 → 새 터미널을 엽니다.
3. 기존 flutter run이 실행 중이면 해당 터미널에서 q로 종료합니다.
4. 아래 명령을 실행하고 Android 기기를 선택합니다.

```powershell
cd C:\AI-Voisk\kiosk_app
flutter run -t lib/main_preview.dart
```

기존 실행에서 r이나 R을 누르는 것만으로는 실행 파일이 바뀌지 않습니다.
원래 주문 화면만 실행하려면 q로 종료하고 `flutter run -t lib/main.dart`를 실행합니다.

## 파일 역할

- role_select_screen.dart: 선택 화면과 준비 중 안내, 고객 서비스 화면 이동
- ../main_preview.dart: 미리보기 앱 시작과 테마 설정
- tests/role_select_test.dart: 역할 안내, 서비스 진입·복귀, 화면 크기 검사

## 팀 통합 시 확인

관리자·점주가 같은 앱 화면인지 별도 웹인지 담당자와 확인 후 연결해야 합니다.
현재 역할 선택 화면에는 로그인이나 권한 검사가 없습니다. 실제 매장 배포 전
관리자·점주 접근 절차를 별도로 구현해야 합니다.
팀장이 공통 시작 화면으로 채택하면 main.dart에서 RoleSelectScreen을 연결하고
필요 없어진 main_preview.dart는 제거할 수 있습니다.

## 검사 결과와 다시 검사하는 방법

공유 전 최종 검사에서 flutter analyze가 문제 없이 통과했고,
기존 서비스 검사 8개와 역할 선택 화면 검사 2개를 함께 실행해 총 10개가 통과했습니다.
main.dart와 main_preview.dart 모두 Android 디버그 빌드·설치·실행에 성공했습니다.
연결된 Android 17 가로 에뮬레이터(1920×1200)에서 선택 화면과 주문 화면의
캡처를 확인했습니다. 주요 화면 배치에 잘림이나 오류 화면은 보이지 않았습니다.
이후 시작 화면을 중앙 버튼 3개로 단순화했고 사용자가 Android 실행 화면을 확인했습니다.
이 디자인 변경 후에도 코드 검사와 전체 자동 테스트 10개를 다시 실행해 통과했습니다.
버튼 조작·옵션 계산·화면 이동은 자동 테스트로 확인했으며, 에뮬레이터에서
모든 조작을 직접 재현한 것은 아닙니다.
실제 갤럭시 탭 A9+의 화면 크기 검증과 서버·음성·결제 통합 검증은 남아 있습니다.

아래 명령은 필요할 때 kiosk_app 폴더에서 직접 실행하는 안내입니다.

```powershell
flutter analyze
flutter test test lib/service/tests lib/home/tests
```
