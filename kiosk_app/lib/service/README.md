# 고객 서비스 주문 화면

AI 보이스크의 고객용 터치 주문 화면 1차 구현입니다.
서버 없이 임시 메뉴 데이터를 사용하며, 메뉴 선택부터 장바구니 수정과 금액 계산까지 동작합니다.
기획 문서의 역할 분담은 초안이며, 이 구현의 담당 범위는 고객 서비스 기능입니다.

새 역할 선택 화면을 포함한 작업물 전체 안내는 [시작 화면 및 작업물 안내](../home/README.md)에 있습니다.
이 문서는 고객 서비스에서 직접 구현한 내용만 설명합니다.

## 화면 구성

- 왼쪽: 세로 카테고리 목록
- 가운데: 음식 아이콘, 메뉴 이름, 가격을 표시하는 메뉴 카드
- 오른쪽: 장바구니, 주문내역 버튼, 합계, 결제하기 버튼
- 오른쪽 위: 직원 호출, 마이크 버튼
- 별도 하단 영역 왼쪽: Language 버튼

가로 태블릿 사용을 기준으로 작업 중입니다. 화면 너비에 따라 메뉴 카드 열 수가 바뀝니다.
스크롤은 유지하고, 목록 끝에서 내용이 늘어나는 효과는 제거했습니다.
음식 이미지는 임시 아이콘이며 실제 사진은 아직 사용하지 않습니다.
갤럭시 탭 A9+ 5G의 실제 화면 크기와 글씨·버튼 크기에 대한 최종 조정은 남아 있습니다.
화면 방향을 가로로 고정하는 코드는 아직 없습니다.

## 구현한 기능

| 기능 | 현재 동작 |
| --- | --- |
| 카테고리 | 전체·식사·국물·사이드·음료별 메뉴 표시 |
| 메뉴 선택 | 큰 선택 창에서 추가 옵션과 수량 선택 |
| 추가 옵션 | 옵션 버튼으로 추가·해제, 옵션 가격을 선택 금액에 반영 |
| 장바구니 담기 | 같은 메뉴·옵션 조합은 수량 합산, 다른 조합은 별도 항목 |
| 장바구니 수정 | 음식 항목을 눌러 현재 옵션·수량 수정, 변경 저장 시 반영 |
| 취소 | 선택 창을 취소하면 기존 장바구니 유지 |
| 수량·삭제 | + / −로 수량 변경, 최소 1개 유지, 휴지통으로 항목 삭제 |
| 합계 | 메뉴 가격과 옵션 가격을 수량에 맞게 합산 |
| 완료 알림 | 담기·수정 완료 후 정중앙 작은 알림 표시, 2.5초 후 사라짐 |
| 직원 호출 시연 | 가운데 안내 창 표시, 닫기 버튼 또는 2.5초 후 닫힘 |
| 버튼 누름 효과 | 직원 호출·마이크·주문내역·결제하기는 누르는 동안만 색 변경 |
| 언어 선택 창 | Language → 한국어·日本語·English·中文 표시, 선택하면 창 닫힘 |

장바구니 수정 결과가 다른 항목과 동일한 메뉴·옵션 조합이면 수량을 합칩니다.
추가 가격은 메뉴 한 개마다 적용됩니다. 앱 종료 또는 다시 시작 시 장바구니는 초기화됩니다.

### 임시 추가 옵션

| 카테고리 | 옵션과 가격 |
| --- | --- |
| 식사 | 밥 추가 1,000원 / 계란 추가 1,000원 / 고기 추가 2,000원 |
| 국물 | 공깃밥 추가 1,000원 / 두부 추가 1,500원 |
| 사이드 | 소스 추가 500원 |
| 음료 | 추가 옵션 없음 |

예: 제육덮밥 9,000원 + 밥 추가 1,000원 + 고기 추가 2,000원 = 한 개 12,000원.
수량을 두 개로 선택하면 24,000원입니다. 실제 메뉴와 옵션은 담당자 합의 후 교체해야 합니다.

## 아직 연결하지 않은 기능

- 서버·DB에서 메뉴 받기, 메뉴 변경·품절 반영, 주문 전송
- 음성 인식과 음성 주문
- 실제 결제와 결제 화면 이동
- 실제 직원 호출 알림 전달
- 주문내역 조회
- 실제 화면 번역
- 주문·장바구니의 영구 저장

직원 호출 문구는 화면 시연용입니다. 실제 직원에게 알림을 보내지 않습니다.
마이크·주문내역·결제하기는 누름 효과만 있으며 실제 처리는 실행하지 않습니다.
메뉴 등록·수정·삭제 및 가격·품절 관리는 점주 파트와 서버 파트에서 연동할 영역입니다.

## 파일 역할

아래 경로는 별도 표시가 없으면 kiosk_app/lib/service 기준입니다.

| 파일 | 역할 |
| --- | --- |
| models/menu_item.dart | 메뉴 모델, 원화 금액 표시 |
| models/menu_option.dart | 추가 옵션 모델, 카테고리별 임시 옵션 |
| data/menu_repository.dart | 메뉴 공급 인터페이스, 임시 메뉴 7개 |
| controllers/cart_controller.dart | 장바구니 상태, 담기·수정·합산·삭제·금액 계산 |
| screens/order_screen.dart | 주문 화면, 선택 창, 언어 창, 알림과 버튼 반응 |
| tests/cart_edit_test.dart | 장바구니 옵션 수정·취소·항목 합산 검사 |
| tests/button_feedback_test.dart | 중앙 알림·자동 닫기·버튼 누름 효과 검사 |
| README.md | 구현 범위, 실행과 검증 안내 |

첫 실행 연결을 위해 서비스 폴더 밖의 kiosk_app/lib/main.dart도 수정했습니다.
Flutter 기본 숫자 세기 테스트였던 kiosk_app/test/widget_test.dart는 주문 화면 검사로 교체했습니다.
관리자·점주·서버·음성 담당 폴더의 코드는 수정하지 않았습니다.

## 이후 연결 지점

- 메뉴: MenuRepository를 구현한 서버용 공급자를 OrderScreen(repository: ...)에 전달합니다.
- 옵션: 현재 sampleOptions를 사용하는 부분을 서버 메뉴 옵션과 연결해야 합니다.
- 장바구니: CartController의 add, setQuantity, update, remove를 사용합니다.
- 항목 식별: 옵션 조합까지 구분하는 CartEntry.id를 수량 변경·수정·삭제에 사용합니다.
- 음성: 현재 화면이 소유한 장바구니와 같은 상태를 사용하도록 연결해야 합니다.
  터치와 음성에서 별도 장바구니를 만들면 주문 내용이 달라지므로 상태 공유가 필요합니다.
- 주문·결제: 서버 전송 형식과 결제 담당자에게 넘길 주문 정보는 아직 확정하지 않았습니다.

## 실행 방법

현재 프로젝트에는 Android 실행 폴더가 있습니다. Web·Windows 실행 설정은 없습니다.

1. Android Studio의 Device Manager에서 가상 태블릿 오른쪽 ▶ 버튼을 누릅니다.
2. Android 홈 화면이 뜨면 가로 방향으로 회전합니다.
3. VS Code에서 프로젝트 폴더 C:\AI-Voisk를 엽니다.
4. 터미널 → 새 터미널에서 아래 명령을 한 줄씩 실행합니다.

```powershell
cd C:\AI-Voisk\kiosk_app
flutter pub get
flutter devices
flutter run -t lib/main.dart
```

기기 선택 목록이 나오면 Android 기기를 선택합니다.
특정 기기로 실행하려면 flutter devices에 나온 ID를 사용해 `flutter run -d 기기ID`를 실행합니다.
실행 중 터미널에서 소문자 r은 코드 변경 반영, 대문자 R은 앱 다시 시작, q는 실행 종료입니다.
R로 다시 시작하면 장바구니가 초기화됩니다.

역할 선택 화면부터 확인하려면 기존 실행을 q로 종료한 뒤 아래 명령을 실행합니다.

```powershell
flutter run -t lib/main_preview.dart
```

관리자·점주는 준비 중 안내만 표시하며, 고객 서비스를 누르면 이 주문 화면으로 이동합니다.
역할 선택 화면은 별도 미리보기 실행 파일로 연결했으며 기존 main.dart의 시작 연결은
역할 선택 화면으로 변경하지 않았습니다.

## 직접 확인할 항목

1. 카테고리를 바꾸면 해당 메뉴만 표시되는지 확인합니다.
2. 옵션 없이 제육덮밥 2개 담기 → 18,000원, 콜라 1개 추가 → 20,000원인지 확인합니다.
3. 장바구니에서 수량 변경과 삭제 시 합계가 갱신되는지 확인합니다.
4. 제육덮밥에 밥·고기를 추가해 2개 담으면 24,000원인지 확인합니다.
5. 장바구니 음식을 눌러 옵션을 해제하고 변경 저장하면 합계가 갱신되는지 확인합니다.
6. 편집을 취소하면 원래 옵션·수량이 유지되는지 확인합니다.
7. 동일 메뉴·옵션 조합은 합쳐지고 다른 옵션 조합은 분리되는지 확인합니다.
8. 중앙 담기 알림이 자동으로 사라지는지 확인합니다.
9. 직원 호출 창의 자동 닫기와 닫기 버튼을 확인합니다.
10. 네 버튼을 누르는 동안 색이 바뀌고 손을 떼면 복귀하는지 확인합니다.
11. Language 선택 창의 언어 표기와 닫힘을 확인합니다.
12. 가로 화면에서 목록 끝까지 스크롤해도 내용이 늘어나거나 잘리지 않는지 확인합니다.

## 검사와 확인 범위

공유 전 최종 코드 검사: flutter analyze 통과, 문제 없음.
서비스 자동 검사 8개와 시작 화면 검사 2개를 함께 실행해 총 10개 통과.
자동 검사는 주문 흐름, 옵션 가격, 수정·취소·합산, 중앙 알림 위치와 자동 닫기,
직원 호출 창, 버튼 누름 효과를 확인했습니다.

사용자가 Android 에뮬레이터에서 초기 화면 실행과 합계·삭제 동작을 확인했습니다.
최종 검사에서는 main.dart와 main_preview.dart 모두 Android 빌드·설치·실행에
성공했으며, Android 17 가로 에뮬레이터(1920×1200)의 화면 캡처를 확인했습니다.
최종 화면의 모든 조작을 에뮬레이터에서 직접 재현한 것은 아니며 기능 검사는
자동 테스트로 수행했습니다. 실제 갤럭시 탭 실행과 서버·음성·결제 통합은 미검증입니다.

kiosk_app 폴더에서 아래 명령으로 전체 검사를 실행합니다.
서비스와 시작 화면 폴더에 둔 검사도 포함하려면 마지막 명령을 사용해야 합니다.

```powershell
flutter analyze
flutter test test lib/service/tests lib/home/tests
```
