# 시연 실행 가이드 (노트북 서버 + 갤럭시 탭)

노트북 한 대에서 서버와 두 대시보드(회사 관리자 웹, 점주 웹)를 켜고, 같은 Wi-Fi의 갤럭시 탭에 키오스크 앱을 설치해 바로 주문해 보는 순서입니다.

```text
갤럭시 탭(키오스크 앱) ── 같은 Wi-Fi ──▶ 노트북 :8001 서버 ── TLS ──▶ Azure MySQL(팀 공용)
                                         노트북 :8080 회사 관리자 웹
                                         노트북 :8081 점주 웹
```

## 1. 준비물

| 어디 | 필요한 것 |
|---|---|
| 노트북 | Windows, Python 3.14, Node.js 22.12 이상, 이 저장소, `server/.env`(DB 접속 정보, 팀에서 받음) |
| 노트북(음성 주문용) | `server/.env`에 `ANTHROPIC_API_KEY=...` 한 줄. 없으면 터치 주문만 됩니다 |
| 태블릿 | 갤럭시 탭(안드로이드 7 이상), 노트북과 같은 Wi-Fi, APK 파일 |

`server/.env`와 API 키, 기기 토큰은 커밋하거나 메신저 단체방에 올리지 않습니다.

## 2. 노트북: 한 번에 켜기

저장소 맨 위의 **`start-demo.bat`을 더블클릭**합니다. 처음 한 번은 서버 패키지 설치와 두 웹 빌드로 1~3분 걸리고, 다음부터는 몇 초면 켜집니다.

준비가 끝나면 창에 아래처럼 나오고, 두 대시보드가 브라우저로 열립니다.

```text
================ AI 보이스크 시연 준비 완료 ================
  회사 관리자 웹 : http://127.0.0.1:8080
  점주 웹        : http://127.0.0.1:8081
  서버           : http://127.0.0.1:8001/docs
  태블릿 서버 주소 : http://192.168.0.23:8001     ← 태블릿에 넣을 주소
  끄기            : 이 창에서 Ctrl+C
```

- 끌 때는 그 창에서 **Ctrl+C**(또는 창 닫기). 서버와 두 웹이 함께 꺼집니다.
- 이미 켜 둔 시연이 있으면 "포트를 이미 쓰고 있습니다"라고 알려 주고 아무것도 하지 않습니다.
- 실행 중에만 적용되는 설정: 두 웹의 접속 허용, 시연 결제·현금 주문 저장(`KIOSK_SAVE_DEMO_PAYMENTS`, `KIOSK_SAVE_CASH_ORDERS`). `server/.env`는 바꾸지 않습니다.

옵션(PowerShell이나 명령 프롬프트에서 `start-demo.bat 옵션`):

| 옵션 | 뜻 |
|---|---|
| `-Backend claude_cli` | API 키 없이, 이 노트북에 로그인된 Claude Code 구독으로 음성 해석 시험 |
| `-NoBrowser` | 브라우저를 자동으로 열지 않음 |
| `-NoWeb` | 서버만 켬 |
| `-Rebuild` | 두 웹을 다시 빌드(코드를 새로 받은 뒤. 보통은 자동) |
| `-Tunnel` | Cloudflare 터널로 https 주소를 열어 태블릿이 어느 네트워크에서든 접속(아래 참고). `start-demo-tunnel.bat`과 같음 |

### Wi-Fi·방화벽 없이: 터널로 켜기(권장)

같은 Wi-Fi, 방화벽 규칙, 공용 Wi-Fi의 기기 간 차단 때문에 태블릿이 붙지 않을 때가 많습니다. **`start-demo-tunnel.bat`을 더블클릭**하면 서버와 두 웹을 켠 뒤 Cloudflare Quick Tunnel을 열고, 태블릿에 넣을 주소를 보여 줍니다(클립보드에도 복사).

```text
  태블릿 서버 주소 : https://xxxx-xxxx-xxxx.trycloudflare.com
```

- 처음 한 번 `cloudflared`를 설치합니다: `winget install --id Cloudflare.cloudflared`. 계정이나 로그인은 필요 없습니다.
- 태블릿은 LTE든 다른 Wi-Fi든 인터넷만 되면 됩니다. 아래 방화벽 설정은 필요 없습니다.
- 서버는 노트북(127.0.0.1)에서만 열리고, 터널로 들어온 요청은 기기 토큰이 필요한 `/kiosk`만 쓸 수 있습니다. 관리자·점주 API와 대시보드는 터널로 열리지 않습니다.
- **주소는 실행할 때마다 바뀝니다.** 키오스크 설정에서 서버 주소를 새로 넣으면 기기 토큰도 다시 넣어야 하므로, 토큰을 안전한 곳에 보관하거나 회사 관리자 웹에서 다시 발급합니다.
- 시연 중에는 노트북이 절전 모드에 들어가지 않게 하고 창을 닫지 않습니다.

### 같은 Wi-Fi로 켤 때: 방화벽과 Wi-Fi

태블릿이 노트북에 붙으려면 8001 포트가 열려 있어야 합니다. 창에 안내가 나오면 **관리자 권한 PowerShell**에서 한 번만 실행합니다.

```powershell
New-NetFirewallRule -DisplayName "AI-Voisk 8001" -Direction Inbound -Protocol TCP -LocalPort 8001 -Action Allow -Profile Private
```

- 이 규칙은 **개인 네트워크**에서만 열립니다. Windows 설정 > 네트워크 및 인터넷 > Wi-Fi > 연결된 네트워크 속성에서 네트워크 프로필이 **개인**인지 확인합니다.
- 카페·학교 공용 Wi-Fi는 기기끼리 통신을 막는 경우가 많습니다. 휴대폰 핫스팟에 노트북과 태블릿을 함께 연결하면 가장 확실합니다.
- 노트북이 공인 IP에 바로 연결된 환경에서는 공용 프로필에 8001을 열지 않습니다(서버가 인터넷에 노출됩니다).

## 3. 대시보드 로그인

| 웹 | 주소 | 로그인 |
|---|---|---|
| 회사 관리자 웹 | http://127.0.0.1:8080 | 관리자 번호(숫자 ID)와 비밀번호 |
| 점주 웹 | http://127.0.0.1:8081 | 점주 로그인 ID와 비밀번호 |

- 계정과 비밀번호는 팀에서 관리합니다(공용 DB에 관리자 1명, 점주 2명이 등록돼 있고 모두 비밀번호가 설정돼 있습니다). 시연 매장(1번)의 점주 계정으로 들어가면 사진이 들어간 메뉴 40개가 보입니다.
- 점주 비밀번호를 모르면 회사 관리자 웹 > 점주 > 비밀번호 초기화로 새로 정합니다. 그 점주의 기존 로그인은 바로 끊깁니다.
- 대시보드는 보안상 **노트북 자신**에서만 열립니다(휴대폰·다른 PC에서는 접속되지 않음).

## 4. 키오스크 기기 토큰 발급

1. 회사 관리자 웹 > **기기** > 태블릿으로 쓸 기기(예: 1번)를 엽니다. 없으면 기기를 추가합니다.
2. **기기 토큰 발급**을 누릅니다. 토큰은 이때 **한 번만** 보이니 바로 태블릿에 입력합니다.
3. 다시 발급하면 이전 토큰은 즉시 쓸 수 없게 됩니다(대기 중인 주문은 버려지지 않고, 새 토큰을 넣으면 다시 보냅니다).

## 5. 태블릿에 앱 설치

설치 파일: `release/AI-Voisk-kiosk-1.2.0.apk` (약 52MB, 모든 안드로이드 기기용).
SHA-256은 같은 폴더의 `.sha256` 파일에 있습니다.

**방법 A. USB 케이블(권장)**

1. 태블릿: 설정 > 휴대전화(태블릿) 정보 > 소프트웨어 정보 > **빌드번호를 7번** 눌러 개발자 모드를 켜고, 설정 > 개발자 옵션 > **USB 디버깅**을 켭니다.
2. 노트북과 USB로 연결하고 태블릿의 "USB 디버깅 허용"을 누릅니다.
3. 노트북에서 실행합니다(안드로이드 SDK의 `platform-tools` 폴더에 `adb`가 있습니다).

```powershell
adb install -r release\AI-Voisk-kiosk-1.2.0.apk
```

**방법 B. 파일 복사**

1. APK를 태블릿으로 옮깁니다(USB 파일 전송, Quick Share, 클라우드 등).
2. 태블릿 '내 파일'에서 APK를 누르고, "출처를 알 수 없는 앱 설치"를 허용한 뒤 설치합니다.
3. Play 프로텍트 경고가 나오면 **세부정보 > 무시하고 설치**를 누릅니다. 팀 내부 시험용 서명(디버그 키)이라 나오는 경고입니다.

앱에는 API 키·DB 비밀번호가 들어 있지 않습니다. 서버 주소와 기기 토큰은 설치 뒤 앱 안에서 입력합니다.

## 6. 태블릿 앱 첫 설정

1. 앱을 켜고 **포장** 또는 **매장 식사** → 주문 화면 왼쪽 아래 **설정 > 키오스크 설정**.
2. **관리자 PIN**(숫자 4~8자리)을 만듭니다. 이후 설정에 들어갈 때마다 이 PIN을 묻습니다(5번 틀리면 5분 잠금).
3. 입력합니다.
   - 서버 주소: 노트북 창에 나온 **태블릿 서버 주소**(예: `http://192.168.0.23:8001`, 터널이면 `https://….trycloudflare.com`)
   - 매장 번호: `1` / 기기 번호: 토큰을 발급한 기기 번호 / 기기 토큰: 4단계에서 받은 값
4. **연결 확인** → "연결 성공: 메뉴 40개 …"가 나오면 **저장**하고 앱을 완전히 껐다 켭니다.
5. 같은 설정 화면에서 필요하면 켭니다.
   - **배터리 최적화 제외**: 절전으로 앱이 꺼지지 않게
   - **화면 고정(Lock Task)**: 고객이 홈 버튼으로 나가지 못하게(처음 켤 때 안드로이드가 확인 창을 띄움)
6. 태블릿 설정에서 **빅스비 음성 호출을 끄고**, 가능하면 Google 음성 인식의 **한국어 오프라인 인식 팩**을 받아 둡니다.
7. 처음 **말로 주문하기**를 누르면 마이크 권한을 묻습니다. 허용합니다.

설정 화면 아래 '상태'에서 서버 연결, 적용한 메뉴 버전, 전송 대기 주문, 최근 주문 내역, 사용성 측정(터치·음성 주문별 평균 탭 수·시간)을 볼 수 있습니다.

## 7. 시연 순서 예시

1. 터치 주문: 떡볶이 → 맵기(필수) 선택 → 담기 → 결제(시연 카드) → 점주 웹 주문 내역에 '터치'로 표시
2. 음성 주문: **말로 주문하기** → "제육 두 개랑 콜라 하나" → "네" → "결제할게요"
3. 상황 추천: "어제 술 마셨는데 해장할 만한 거 추천해 줘" → 추천 카드 3장
4. 필수 옵션 되묻기: "떡볶이 하나" → "매운 걸로"
5. 점주 웹에서 메뉴 품절·가격 변경 → 태블릿에 바로 반영(진행 중인 주문이 있으면 주문이 끝난 뒤)
6. 점주 웹 AI 추천 설정에서 정책을 '매장 이익 우선'으로 → 같은 질문에 추천 순서 변화
7. 키오스크 **직원 호출** → 점주 웹에 알림

## 8. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 연결 확인에서 "서버에 연결하지 못했습니다" | 같은 Wi-Fi인지, 노트북 창이 켜져 있는지, 방화벽 규칙과 네트워크 프로필(개인), 노트북 IP가 바뀌지 않았는지. 계속 안 되면 `start-demo-tunnel.bat`으로 켭니다 |
| 메뉴 변경이 태블릿에 30초쯤 늦게 반영됨 | 서버 가상 환경에 `websockets`가 없으면 실시간 알림이 꺼지고 30초 주기 확인으로만 동작합니다. `start-demo`가 `requirements.txt` 변경을 감지해 자동으로 다시 설치합니다 |
| "기기 토큰이 맞지 않습니다" | 토큰을 다시 발급했거나 오타. 회사 관리자 웹에서 새로 발급해 입력 |
| 음성 주문이 "화면으로 주문해 주세요"로 끝남 | `server/.env`의 `ANTHROPIC_API_KEY`, 또는 `-Backend claude_cli`로 시험 |
| 마이크가 반응하지 않음 | 앱 마이크 권한, 빅스비 호출 끄기, 태블릿 음성 인식 언어(한국어) |
| 대시보드 로그인이 안 됨 | 주소를 `127.0.0.1`로 열었는지(`localhost`도 가능), 계정 비밀번호 |
| 메뉴 사진이 안 보임 | 사진은 서버를 켠 노트북의 `server/media/menu`에 있습니다. 다른 노트북이면 `server\.venv\Scripts\python.exe server\seed_menu_images.py --force`로 다시 받거나 점주 웹에서 올립니다 |
| "포트를 이미 쓰고 있습니다" | 이미 켜 둔 시연 창을 닫거나, 표시된 PID의 프로그램을 끄고 다시 실행 |

## 9. APK 다시 만들기

코드를 고친 뒤 태블릿용 APK를 다시 만들 때(Flutter 3.47, JDK 21 필요):

```powershell
cd kiosk_app
flutter build apk --release
copy build\app\outputs\flutter-apk\app-release.apk ..\release\AI-Voisk-kiosk-1.2.0.apk
```

- 버전은 `kiosk_app/pubspec.yaml`의 `version`과 `lib/core/kiosk_services.dart`의 `appVersion`을 함께 올립니다(테스트가 둘이 같은지 확인).
- 시연 서버가 HTTP라 release 빌드도 평문 HTTP를 허용합니다(`android/app/src/main/res/xml/network_security_config.xml`). 실제 매장에 HTTPS 서버를 두면 이 설정을 끕니다.
- 지금은 디버그 키로 서명합니다. 스토어 배포나 외부 배포 전에는 별도 서명 키를 만들어야 합니다.
